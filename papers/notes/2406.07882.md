## Research question and main claims
Can a chatbot's internal "user model" be read out and controlled with linear probes, and do users benefit from a dashboard that shows and lets them edit it?
Claims:
1. LLaMa2Chat-13B linearly encodes the user's age, gender, education and socioeconomic status (SES) in its residual stream; reading probes reach 0.94-0.98 validation accuracy.
2. Translating activations along probe directions causally changes responses in the direction of the target attribute (intervention success 0.93-1.00 with "control" probes).
3. Probes trained at the token where the model is about to answer the user ("control probes") steer better than probes trained at an explicit attribute-reading prompt ("reading probes"), although they read slightly less accurately.
4. In a 19-person user study, users valued seeing/controlling the user model, and it exposed biased behaviour.

## Methodology (probe and steering recipe)

### Model
LLaMa2Chat-13B, official Meta checkpoint on HuggingFace (repo: `meta-llama/Llama-2-13b-chat-hf`, loaded in half precision). Residual stream width 5120; 40 layers (41 hidden states including embeddings). Context window 4096 tokens.

### Synthetic conversation dataset (Sec. 4.1, Table 1, Appendix A/B)
No real human-chatbot data with demographic labels existed, so conversations were generated by LLM role-play using **GPT-3.5-Turbo and LLaMa2Chat-13B**: one prompt produces a whole multi-turn conversation with both sides.
- Total 13,900 multi-turn conversations, average 7.5 turns; 1,000 to 1,500 conversations per subcategory; no duplicates.

| Attribute | Subcategories | # Convos | GPT-4 consistency | Topics | Hidden correlation |
|---|---|---|---|---|---|
| Age | Child (<13), Adolescent (13-17), Adult (18-64), Older Adult (>64) | 4000 | 88% | 171 | 0.0% |
| Gender | Male, Female | 2400 | 93% | 101 | 0.5% |
| Education | Some Schooling, High School, College & Beyond | 4500 | – (not reported) | 158 | 0.7% |
| SocioEco | Lower, Middle, Upper | 3000 | 95% | 109 | 1.3% |

- Generation prompts (Appendix A), e.g. gender prompt 1 (used for 72% of the gender data): "Generate a conversation between a human user and an AI assistant. This human user is a {gender}. Make sure the conversation reflects this user's gender. Be creative on the topics of conversation. The user's response should start with '### Human:', and the AI assistant's response should start with '### Assistant:'". Gender prompt 2 (28%) adds "This may be reflected by how they address themselves or their partner." Age prompts: "This human user is a {age} who is {year_range}. Make sure the topic of the conversation or the way that user talks reflects this user's age. You may or may not include the user's age directly in the conversation." (two variants, 50% each). Education: three variants (66% / 17% / 17%). SES: two variants (50% / 50%), the second saying the conversation should reflect that the user "belongs to {class_name} class but not {other_class_name}".
- System prompts during generation: GPT-3.5-Turbo: "You are a chatbot who will actively talk with a user and answer all the questions asked by the user." LLaMa2Chat-13B: the default Llama-2 system prompt ("You are a helpful, respectful and honest assistant. ...").
- Quality control with GPT-4: (a) consistency = GPT-4's classification of the role-played user's attribute vs assigned label; (b) topic diversity; (c) hidden correlation = whether users show attributes beyond the assigned one. Age disagreements mostly between adjacent groups (child/adolescent 6.9%, adult/older adult 3.9%). Non-binary gender was dropped (model conflated it with sexual orientation).

### Reading probes (Sec. 4.2)
- Linear logistic probe p(X) = sigmoid(<X, theta>), theta in R^5120, one-versus-rest (one output per subcategory), L2 regularisation.
- **Input:** residual-stream representation at the **last token of a special assistant-turn stub appended after the last user message: "I think the {attribute} of this user is"**.
- Separate probe per layer; 80/20 train/validation split stratified by subcategory.
- (repo, `notebooks/train_probes/train_read_and_controlling_probes.ipynb`, `src/dataset.py`, `src/probes.py`): the conversation is rendered in Llama-2 chat format with the last assistant reply removed, so the text ends with the last user message followed by `[/INST]`; for reading probes the string `" I think the {age | gender | socioeconomic status | education level} of this user is"` is appended; tokenised with `max_length=2048`; activations = `output_hidden_states` at position `-1` for all 41 layers. Probe = single `nn.Linear(5120, n_classes)` + sigmoid, trained with `nn.BCELoss` on one-hot labels, Adam lr 1e-3, betas (0.9, 0.95), weight decay 0.1, ReduceLROnPlateau (factor 0.75, patience 0), batch size 200, 50 epochs, `random_state=12345`.

### Control probes (Sec. 5)
- Identical training set-up, but the **input is the residual-stream representation at the ending token of the last user message** (i.e. where the model starts answering; no "I think the ... is" stub). (repo: with `control_probe=True` nothing is appended, so the position is the final token of the `[/INST]` tag.)
- Rationale: this representation "contains information for the chatbot to answer requests from different synthetic users".

### Steering / intervention (Sec. 5, 5.1, Appendix M)
- Translate the representation: x_hat + N * theta_control (theta = probe weight vector of the target subcategory).
- **Layers 20 to 29** residual stream, **strength N = 8** for all questions; layers and strength chosen on a few questions outside the test set.
- Applied to the **last input token representation, repeatedly at every generation step** until the response is complete.
- For the reading-probe comparison, representations are translated by the same L2 distance along the reading-probe weight vector.
- Greedy decoding.
- (repo, `notebooks/causality_tests/causality_test_on_gender.ipynb`, `src/intervention_utils.py`): implemented with `baukit.TraceDict` editing the output of decoder blocks `model.layers.{19..28}` (`from_idx = 19`, `to_idx = 29`, exclusive), adding `one_hot_target @ probe.proj[0].weight * N` to position `-1`; the probe used for block k is the one trained on hidden state k+1; the weight vector is **not** unit-normalised in the default path; `max_new_tokens=768`, `do_sample=False`. The gender notebook sets `N = 7` (paper says 8). The notebooks also generate an "unintervened" baseline and a **random-direction control** (`rand='gaussian'`: Gaussian vector rescaled to the probe row's L2 norm) — this control is not reported in the parts of the paper I read.

### Measuring behaviour change (Sec. 5, Appendix E, G)
- 30 questions per attribute (120 total) whose answers plausibly depend on the attribute, e.g. gender: "Hi! How should I style my hair for a formal event? Suggest two hairstyles."; SES: "Hi! What car brands do you think are best for me? Can you list three car brands?"; education: "Explain the central dogma of molecular biology."; age: "Can you suggest some fun outdoor activities for me?" Full lists in Appendix E and in `code/TalkTuner-chatbot-llm-dashboard/data/causality_test_questions/{age,gender,education,socioeco}.txt`.
- For each question, generate a pair of responses under contrasting interventions: older adult vs adolescent; female vs male; college-and-beyond vs some schooling; high SES vs low SES.
- Judge: `gpt-4-turbo-preview`, temperature 0, prompt: "Please answer which one of the following responses is more targeted to a {demographic} user. Think through it step by step and then respond with a JSON object that contains 'scratchpad' and 'answer' where 'answer' should be either '1' or '2'. Note that the answer field _must_ be '1' or '2'. You must give an answer. Do not output anything else." Response order (1/2) and which demographic is named are both randomised.
- Success = GPT-4 correctly matches each intervened response to the attribute used.

### Prompting baselines for reading (Appendix D, Table 3)
- User Prompt: "Based on our conversation, what do you think my {demographic} is? You answer should be one of {subcategory1, ... subcategoryn}. Do not add other details in your response."
- System Prompt: same question inserted as a system message at the end.
- Chatbot Prompt: force the assistant turn to start with "Based on the conversation, given the options {...}, I think the {demographic} of this user is".

### Real-text generalisation (Appendix C)
PANDORA Reddit comments with gender labels (3,044 users: 1,727 male, 1,317 female). Five comments per user placed in a user message: "Hi. I recently left these comments on the Reddit: 1. ... 5. ... Based on the comments I left, what do you think my gender is?" then the reading stub "I think the gender of this user is".

### User study (Sec. 7-8)
19 participants, within-subject, three UI conditions, three tasks; Wilcoxon signed-rank tests; grounded-theory coding. Not relevant to our probing design beyond showing the probes work on real typed text.

## Key quantitative results
- **Table 2 — intervention success rate (30 questions each):** Control probes: Age 1.00, Gender 0.93, Education 1.00, SocioEco 0.97. Reading probes: 0.90, 0.80, 0.87, 0.93.
- **Table 2 — best validation reading accuracy across layers:** Control: 0.96, 0.91, 0.93, 0.95. Reading: 0.98, 0.94, 0.96, 0.97. Validation sizes 800 / 480 / 900 / 600.
- **Figure 1:** reading-probe validation accuracy rises with depth across the 40 layers (roughly 0.4-0.7 in the first layers to above 0.9 by about layer 20-30; exact per-layer numbers not printed).
- **Table 3 — prompting vs probing accuracy (Age / Gender / Education / Socioeco):** User Prompt 0.48 / 0.10 / 0.60 / 0.41; System Prompt 0.49 / 0.69 / 0.60 / 0.58; Chatbot Prompt 0.60 / 0.86 / 0.45 / 0.77; Control Probe 0.96 / 0.91 / 0.93 / 0.95; Reading Probe 0.98 / 0.94 / 0.96 / 0.97. The model refused to guess gender in 88% of conversations and SES in 37%; without the "Do not add other details" sentence gender accuracy was 0.02. Logit lens (Fig. 7) shows the correct attribute predicted in intermediate layers and overridden in the last two layers — i.e. **the model's verbal report understates what it internally represents**.
- **Figure 5 (layer 30):** final reading / controlling accuracy: Age 0.98 / 0.96, Gender 0.93 / 0.90, SocioEco 0.97 / 0.95, Education 0.95 / 0.92; final train sizes 3200 / 1920 / 2400 / 3600. Accuracy stabilises after about **300 to 500 synthetic conversations per subcategory**.
- **Reddit (Appendix C):** reading probe balanced accuracy 0.85 without fine-tuning; control probe 0.70.
- **Dose response (Fig. 17):** increasing N on the high-SES direction monotonically increases the price of recommended cars and the "most expensive NYC apartment" rent.
- **Qualitative (Appendix F/H):** steering changes tone and register as well as content: emoji and "Hey there!" for adolescent; "Good day to you, sir/madam!" for upper class; child-level metaphors for "some schooling". Control-probe steering changes greeting/tone consistently; reading-probe steering changed content but kept the original greeting.
- **Appendix M:** explanation offered: translating along the (most discriminative) reading direction pushes activations out of distribution, whereas the control direction keeps them in distribution (2D projection at layer 26).
- **User study:** user-model accuracy 78% averaged over age/gender/education after six turns; accuracy averaged over turns 70.4% for men vs 58.6% for women; users wanted to see the user model 6.11 (1.49) / 7 and use controls 6.00 (1.05) / 7.
- Compute: one A100 80 GB; about 3 minutes per probe.

## Controls for confounds
- GPT-4 audit for label consistency and hidden attribute correlations (0.0%-1.3%).
- Claim that rising accuracy with depth means the probe "is not simply picking up information from the raw conversation text" — suggestive, not a control. **No bag-of-words / surface-feature baseline classifier on the conversation text is reported, and no control for length, vocabulary or topic.** Because the synthetic users were told to make the attribute evident, lexical cues (and topic) certainly separate the classes; the probes could be reading topic/lexical content.
- No random-direction or shuffled-label steering baseline reported in the paper sections read (one exists in the repo notebooks).
- Judge order and target label randomised.
- Synthetic-to-real transfer checked only for gender (Reddit).
- Intervention layers/strength tuned on held-out questions.

## Limitations
Stated: one model only; synthetic training data (should be compared with human data; effect of different generation prompts unexplored); steering assumes attributes are represented independently; small, highly educated user-study sample.
Noticed by me: (a) training data is LLM-written on both sides, so the "user" text is LLM-style text role-playing a demographic — probes are trained on exactly the kind of text our project treats as "LLM-authored prompts"; (b) only 30 test questions per attribute and a single GPT-4 pairwise judgement, no confidence intervals; (c) pairwise judge only shows the two steered outputs differ in the expected direction, not that either differs from the unsteered output; (d) the same intervention changes style and content together, so off-target effects are not quantified; (e) paper/code mismatch on N (8 vs 7 for gender).

## Relevance to our project
- **Reusable recipe for a "prompter is an LLM vs a human" probe:** treat authorship as a user attribute.
  - Reading probe: append an assistant stub such as "I think the author of this message is" (my adaptation) after the user turn and take the last-token residual at every layer; train one logistic probe per layer; pick the layer by validation accuracy.
  - Control probe: train on the last token of the user turn (end of `[/INST]` / chat-template user terminator) with no stub; use its weight vector for steering.
  - Steering: add N x weight to the last-token residual at about 10 consecutive mid-to-late layers (20-29 of 40 here, i.e. roughly 50-72% depth) at every generation step; tune N on held-out prompts; sweep N for a dose-response curve.
  - A few hundred examples per class suffice (300-500).
  - Evaluate steering with paired outputs and a blind LLM judge with randomised order; add the unsteered and random-direction baselines that the paper omits.
- **Design implications:** (1) Verbal self-report is unreliable for what the model represents about the user (88% refusals, logit-lens override), so asking the model "was this written by an AI?" is not a substitute for probing. (2) Steering a user-attribute direction changes register and helpfulness (shorter answers, withheld options, refusals to rank car brands for "lower class"), which is precedent that a "user is an LLM" direction could shift refusal/compliance. (3) The probe-vs-surface-feature question is unresolved here, so our study must include text-only baselines (bag-of-words / length / the 21 stylistic features from 2409.08330) and length- and content-matched pairs, and should test whether the probe direction still separates classes after projecting out those features. (4) The existing Llama-3.1 and Gemma-2 code path in `dashboard_v1/probing` can be adapted directly.
- **Gap left open:** the paper never considers "human vs AI" (or evaluator vs real user) as a user attribute, never tests safety behaviours (refusal, sycophancy), and its training "users" are all LLM-written, so it says nothing about whether the model distinguishes human-written from LLM-written prompts.
